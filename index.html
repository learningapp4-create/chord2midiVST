Current capabilities

This page and the VST3 share one phrase: eight chords by default, one chord per bar in 4/4. Bass and treble are separate patterns on the same MIDI channel.

  • 24 styles from the ChordCanvas beat catalog, listed below. The browser uses the same style rows as the plugin.
  • Key of C, C#, D, Eb, E, F, F#, G, Ab, A, Bb, or B. Changing key transposes the current line. The status line names the key the style was catalogued in.
  • An editable chord line. Style chords reloads that style's line. New progression builds eight chords in the key: four diatonic degrees (I, ii, iii, IV, V, or vi, sometimes a major III or a minor iv), each with a colour tone, then the same four roots with a new colour.
  • Tempo from 40 to 200. Choosing a style sets tempo and feel to that style. Tempo is what Hear and the .mid file use.
  • Feel: Straight (on the grid), Human, or Loose. Human and Loose lay some notes back. The drift is deterministic, so Hear and the file match.
  • Voicing: Shell (root and guide tones), Close (the chord in one register), or Full (a low root and fifth, plus the upper chord; wide styles also double the treble up an octave).
  • Rhythm: Style (that style's bass and treble grids, including its rest cycle), or an override: Block (quarter-note chords), Climb, Fall, or Pairs.
  • Note envelope, in beats measured from each note: attack (silence up to the peak), decay (peak down to sustain), sustain (the held level, 0–100%), and release (fall to silence after the written note). Hear follows that curve. The MIDI file writes it as expression (CC11) so a DAW sees the contour, not only one velocity.
  • Phrase volume, 0–100%. It scales Hear, every note velocity, and every expression value. It does not change the envelope shape.

How MIDI reaches a track

  • Download MIDI on this page writes a Standard MIDI file of the phrase you are hearing. Drop that file onto a DAW track. This is the path that works in the browser.
  • Hear plays that same phrase through the browser, with a sine preview and a moving piano roll. It does not send MIDI to a DAW by itself.
  • Native plugin only. In a DAW, the VST3 sends note-on and note-off while the host plays (the DAW tempo wins), and the plugin window can drag or save the same kind of .mid file. Those controls are not available on this web page, because a browser cannot host the VST3.

The file is a type-1 Standard MIDI file, 960 ticks per quarter, one track named Chord2MIDI, a tempo event, and a 4/4 time signature. Note-on velocity is the style accent scaled by phrase volume. CC11 expression is the per-note envelope, also scaled by phrase volume, merged on one channel as the loudest note at each moment. Hear multiplies accent, envelope, and phrase volume once. Overlapping copies of the same pitch are shortened so a note-off lands before the next note-on. A release tail is kept when the next same pitch leaves room. Note times, pitches, velocities, and expression match the C++ phrase engine.

Styles

Each style is the ChordCanvas beat of that name: its chord line, tempo, treble pattern, bass pattern, rest cycle, and timing feel. Grids are onsets per bar (a quarter note is one beat; a bar is four). A rest cycle such as 2-2-4 counts onsets and leaves a gap each time the count hits the next number. Patterns are block chords, a single rising or falling line, or adjacent pairs.

Symbols match the catalog, with two normalizations: Emsus2 is played and printed as Esus2, and Gsus as Gsus4. That shows up in Heartfelt and Relieve. Pitch names use one spelling (F#, Bb, Eb, Ab, C#), including after you transpose.

What this iteration added

  • A per-note envelope: attack, decay, sustain, and release, in beats. Hear follows it. The MIDI file writes the same curve as CC11 expression, and keeps the style accent in note velocity.
  • Phrase volume from 0 to 100%. It scales Hear and every note and expression value in the .mid, without changing the envelope shape.
  • The same controls on the VST3 editor. Host playback sends the expression along with the notes.
  • Tests that check the envelope curve, the CC11 contour, and phrase-volume scaling against the C++ engine.

Iteration 1 is still here: the 24 styles, key, tempo, feel, voicing, rhythm, editable chords, the VST3, and this page's Hear and MIDI download.

Still missing

These stay in a native build. The browser demo does not do them:

  • Loading the VST3 in a DAW, host-synced note output, and dragging a .mid file out of the plugin window.
  • A Mac or Windows plugin binary, and AU or AAX. The Linux .vst3 will not load on those systems.

These are still missing from the phrase itself, in the browser and in the plugin:

  • ChordCanvas can stack up to ten rows (intro, verse, chorus, and so on). This phrase is one row.
  • No separate sub-bass lane, no sustain-pedal CC, and no bass rest cycle of its own. Rests follow the treble cycle. The bass plays its grid.
  • Pattern modes here are block, climb, fall, and pairs. Later ChordCanvas modes (walk, guide, zigzag, bebop, approach, lick, resolve) are not in these 24 styles and are not implemented.
  • No multi-layer instruments, reverb, or WAV bounce. Hear is a plain tone, not the ChordCanvas piano.
  • Voicing is shell, close, or full. It is not a note-for-note copy of every ChordCanvas register.
  • Feel is a laid-back drift with its own timing, not a transcription of ChordCanvas's delay formula.
  • New progression is a diatonic 4+4 colour loop. It is not the full Imagine feature.
  • Incoming MIDI is ignored. Nothing here yet triggers chords from a keyboard.

Build

Built on Linux x86-64 with gcc and g++ 13.3.0 (CMake 3.28, Release). phrase_tests passed. The VST3 is build/Chord2MIDI_artefacts/Release/VST3/Chord2MIDI.vst3, an ELF shared object at Contents/x86_64-linux/Chord2MIDI.so. The standalone app is build/Chord2MIDI_artefacts/Release/Standalone/Chord2MIDI. No DAW was available here, so the plugin was not loaded in a host. libcurl and webkit2gtk were not installed; this build turns the JUCE web browser and curl off. The page you are reading is the way to hear the phrase without that plugin.

Configure with cmake -S . -B build -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++ -DCMAKE_BUILD_TYPE=Release, then cmake --build build. Pin both compilers: the default c++ on the build machine was Clang and could not link libstdc++. CMake downloads JUCE 8.0.8. It is not stored in this repo. Phrase tests alone: -DCHORD2MIDI_BUILD_PLUGIN=OFF.

A Mac or Windows DAW still needs this project built on that platform (Xcode or Visual Studio), producing a .vst3 for that OS. The Linux bundle will not load there. Before shipping a binary, pick the JUCE licence you are actually using: AGPLv3 (and keep the JUCE splash screen) or a commercial JUCE licence. Details are in THIRD_PARTY_NOTICES.md. The Steinberg VST3 SDK arrives inside JUCE under its own terms.
